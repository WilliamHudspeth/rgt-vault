# ASVS 4.0: V4 (Access Control) and related identity requirements (Go line, batch H1)

**Line of record:** Go (`go/`). The Python line is end-of-life. It still has the shared token and the self-asserted agent, and nothing below uses it as evidence.
**Verified against:** `origin/master` `3e66269` plus branch `feat/h1-agent-identity`. File references use symbol names because line numbers drift. Every verdict below was checked in Go code and by Go tests run with `-race`. Older issue comments and older docs were not used as evidence.

## Design (B1 default, implemented)

- **Per-agent token store** (`go/internal/auth/store.go`, `Store`). The file `~/.config/rgt-vault/tokens.json` is 0600 inside a 0700 directory. It maps `sha256(token)` to `{id, agent_id, scopes, created_at, expires_at?}`.
  - Writes take a lock file and replace the store with an fsynced temp file and a rename.
  - Reads re-load the store when it changes on disk. The check uses file identity (`os.SameFile`), size and mtime, so a revoke takes effect on a running server.
  - The plaintext token exists only in the return value of `Mint` / `Rotate`.
- **Subject from the token** (`go/internal/server/handlers/identity.go`, `subject` / `querySubject`). Every handler takes the ABAC subject from the authenticated `auth.Principal`. A request that names a different agent (`agent`, `agent_id`, `operator`, `?agent=`) gets 403 and an `AUTHZ_DENIED` row.
- **One authorization table** (`go/internal/server/authz.go`, `routeRequirement`), enforced in `AuthMiddleware` before any handler runs:
  - `operator`: `/v1/requests*` and `/v1/rotate`.
  - `audit` or `operator`: `/v1/audit` and `/v1/audit/verify`.
  - `agent` and `lease`: `POST /v1/secrets/{ns}/{name}/lease`.
  - `agent`: everything else.
  - The vault then applies ABAC with the token's agent.
- **Authentication failures** (`AuthMiddleware`, `authFailure`, `failureLimiter`).
  - Missing, unknown, revoked and expired tokens all get the same generic 401.
  - Each failure writes an `AUTH_FAILED` row with the IP, route, reason and a short id. The short id is the store record id, or an 8-hex sha256 prefix. The token itself is never written.
  - More than 10 failures per source address per minute get 429, and the window gets one `AUTH_RATE_LIMITED` row. A valid token from that source is always served.
- **Legacy mode.** `serve --legacy-shared-token` keeps the pre-H1 behaviour and logs `servecmd.LegacyWarning`. It is never the default.
- **Plaintext route (RGT-504).**
  - Removed: `GET /v1/secrets?name=`, which now returns 400.
  - Added: `POST /v1/secrets/{ns}/{name}/lease`, which needs the opt-in `lease` scope.
  - The response is sent with `Cache-Control: no-store`. The lease goes through `vault.Lease` (ABAC read, approval, 2FA, rate limit, honeytokens) and writes a `SECRET_READ` row.

Verdict key: **Satisfied** (`Closes`), **Partial** (`Refs`, part of the requirement is unmet), **Gap** (`Refs`, not met), **Refs-only** (another batch owns the issue; this PR adds evidence).

## Gaps and follow-ups

1. Static bearer tokens: no idle timeout, no session exchange (RGT-318, RGT-328, RGT-337).
2. Legacy shared-token mode still exists (RGT-235, RGT-295). Remove it after one release.
3. `purpose` is client-declared (RGT-343).
4. Client token files are plaintext at rest, mode 0600 (RGT-246). OS keyring storage for client tokens would close this.
5. RGT-504 deviation (lease scope instead of operator scope) needs sign-off.
6. No HTTP API for token management. This is deliberate: tokens are managed only by whoever can write the store file on the host.
7. Each failed authentication still costs one hash and one audit row, up to the per-source limit. With 4096 tracked sources, a distributed source set can still write rows. The server binds to loopback by default.
