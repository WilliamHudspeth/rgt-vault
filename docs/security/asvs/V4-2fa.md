**Verified against:** `origin/master` `cbe6590` plus branch `feat/h2-approval-2fa`. Every verdict was checked in Go code and by Go tests run with `-race`. Older issue comments and older docs were not used as evidence.

## What changed

| Area | Behaviour now | Code |
|---|---|---|
| Bad TOTP codes on `POST /v1/requests/{id}/approve` | Counted per request (cap 5: the request is **denied**, `DecidedBy` `system`) and per operator token (10 within the lockout window: the operator is **throttled**, 429 + `Retry-After`, and no code is checked, so a correct code is not consumed). Every bad code writes `APPROVAL_BAD_CODE`; the row has request id, token id, IP and `attempt=n/limit`, never the code. A missing code is audited but not counted. | `approval.Broker.ApproveBy`, `CodeError`, `ThrottleError`; `handlers.reportApprovalFailure` |
| TOTP reuse | The server always builds the replay-guarded verifier. A reused code (same step, or an older step than the last accepted) is refused, written as `APPROVAL_CODE_REPLAY`, and sent to the notifier (log line, optional webhook). It is distinguished from a typo. | `totp.ReplayGuardedVerifier.VerifyResult`, `server.OpenStack` |
| Separation of duties | A request is pinned to the token that made it. A token cannot approve a request made with the same token id, and no token of the same agent can either. An approver that cannot prove an identity is refused. 403 + `APPROVAL_SOD_DENIED` + notification. Deny is always allowed. | `approval.separation`, `handlers.AuditHTTP` (`WithRequester`) |
| Request expiry | Unchanged and now tested through HTTP: after the timeout the agent gets a denial (`DecidedBy` `system`) and an operator can no longer approve it. | `Broker.lookup`, `Ticket.Wait` |
| `require_2fa` downgrade | A new version without `require_2fa` after a newest version (any status, a revoked one included) that had it is refused (403, `REQUIRE_2FA_DOWNGRADE_DENIED`) unless the token has the operator scope. The check runs in the same SQLite transaction as the insert. A permitted downgrade writes `REQUIRE_2FA_DOWNGRADED`. The legacy shared token never counts as operator for this. | `store.SetSecretChecked`, `vault.setSecret`, `handlers.SetSecret` |
| Approval for `set` / `rotate` / `revoke` | Opt-in: `serve --require-approval-for set,rotate,revoke` (or `all`; env `RGT_VAULT_REQUIRE_APPROVAL_FOR`). Default is none. Reads stay under `--require-approval`. Only requests the ABAC policy would allow reach the operator. `set` and `revoke` ask for a TOTP code when the secret has `require_2fa`; `rotate` when a TOTP secret is configured. | `approval.ParseGatedOps`, `handlers.gate` |
| Capability tokens | `serve --harness-key-file` now wraps the verifier in a replay guard: each token is accepted once until its own expiry. The cache is bounded, purged of expired ids on every accept, and refuses new tokens when full of live ids (it never evicts a live id). Replays are `CAPABILITY_DENIED` rows with `TokenReplayError`. | `captoken.ReplayGuard`, `server.OpenStack` |
| TOTP secret file | Created 0600 by the open call (`os.CreateTemp`, then moved into place; there is no chmod after the write). The server refuses a TOTP file that group or others can read (POSIX). | `cmd/rgt-vault/files.go`, `server.readTOTPSecret` |
| `enroll-2fa --force` | Needs an operator token when the token store has one; prints a warning; writes `TOTP_SECRET_REPLACED` with `old_secret_fingerprint` (first 8 hex digits of sha256 of the old secret) and the operator token id; refuses if the row cannot be written. | `cmd/rgt-vault/enroll.go` |
| Token mint / rotate / revoke / import | Each prints a `WARNING`, writes `TOKEN_MINTED` / `TOKEN_ROTATED` / `TOKEN_REVOKED` / `TOKEN_IMPORTED` (token id, agent, scopes, expiry, OS user; never the token), and sends the event to `$RGT_VAULT_SECURITY_WEBHOOK_URL` when set. If a vault exists and the row cannot be written, the new token is revoked again. | `cmd/rgt-vault/tokenaudit.go`, `token.go` |

Server-side notifications go to the log (always) and to `--security-webhook-url` (optional; loopback unless `--security-webhook-allow-remote`; netguard dial check, no redirects, no proxy, bounded concurrency). Payloads carry the event name, request id, agent, token id and a short description; never a code, token or secret value (`TestH2*` `assertNoCode`, `TestCLISecurityWebhookNotifiesTokenAndTOTPChanges`).

## Audit events added

`APPROVAL_BAD_CODE`, `APPROVAL_CODE_REPLAY`, `APPROVAL_AUTO_DENIED`, `APPROVAL_LOCKOUT`, `APPROVAL_THROTTLED`, `APPROVAL_SOD_DENIED`, `APPROVAL_APPROVED`, `APPROVAL_DENIED` (also for a denied gated set/rotate/revoke), `REQUIRE_2FA_DOWNGRADE_DENIED`, `REQUIRE_2FA_DOWNGRADED`, `TOTP_SECRET_REPLACED` (now with fingerprint and operator), `TOKEN_MINTED`, `TOKEN_ROTATED`, `TOKEN_REVOKED`, `TOKEN_IMPORTED`.

## Operational notes

- **Approver of a gated rotation or a self-requested action** must be a different token *and* a different agent id than the requester. Mint a second operator token for another agent id (`rgt-vault token mint --agent ops2 --scope operator`).
- **Lockout is per operator token id** (and per request). Defaults: 5 bad codes per request, 10 per operator within 5 minutes. `StackOptions.ApprovalCodeAttempts`, `ApprovalOperatorFails` and `ApprovalLockout` tune them for embedders; there is no CLI flag for them yet.
- **Operator state is in memory and bounded** (1024 operators). If the table is full of live entries a new operator is not tracked, but the per-request cap still applies.
- **Webhook**: set `RGT_VAULT_SECURITY_WEBHOOK_URL` for the CLI (token and enrol events) and `--security-webhook-url` for the server. A dead webhook never blocks an operation; it prints or logs a warning (the URL is not printed because it may carry a key).
- **Behaviour changes to know about:** the agent token used as the operator token in legacy mode can no longer approve its own request; a `set` that omits `require_2fa` on a secret that has it is now refused for non-operators (send `"require_2fa": true`); a TOTP file with a group/other-readable mode is refused at startup on POSIX.
